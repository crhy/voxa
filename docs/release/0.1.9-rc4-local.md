# Voxa 0.1.9 rc4 — local Flatpak (not published)

This is a **local test bundle** for 0.1.9, built from this checkout and **not** pushed to
Flathub or the GitHub Pages repo. It is rc3 plus the three fixes from issue #72 (branch
`strata/v06-voxa-voxatest-echo-on-fix`) that make a live VoxaTest run work **with echo
cancellation ON**. Use it to try the hearing loop with DTLN on your own machine; it never
auto-updates and never overwrites the Flathub 0.1.8 you had.

## What is in it

Everything in rc3 (`docs/release/0.1.9-rc3-local.md`): APP_VERSION `0.1.9`, the whole hearing
chain (f163..f183, #72), the DTLN-aec default echo stage (h04), the four rc2 loop fixes and the
Ollama installer gate. New since rc3 (issue #72, "live tests with echo ON"):

- **The reference was still empty on the prepared paths (Bug 1, `voxa/timeline.py`).** rc3 fixed
  the tap for pipelines with a named sink, but `_play_file` hands a **playbin** the file, and a
  playbin builds its sink chain inside itself: the tap found "no sink element to tap in front
  of" and every heard line in the v05 run said `reference silent: no echo possible`, even with
  DTLN on. The tap now hands the playbin its own sink — a tee in a bin set as `audio-sink`,
  feeding a real sink and the F32 tap branch, so the playbin chains volume/convert/resample in
  front of it and the reference again holds the exact PCM after mixing, gain and ducking. The
  same fix covers the media player's playbin (`voxa/agent/player.py`).
- **VoxaTest refused echo cancellation (Bug 2, `voxatest/`).** The preflight guard refused every
  non-off echo mode — written for a canceller that listens to the *whole system output*. DTLN,
  Voxa's own stage and AEC3 reference **Voxa's own playback**, so VoxaTest's spoken prompts
  (played by another process, never in that reference) survive them; the refusal forced
  `echo_mode: off`, and the v05 run then measured 79 self-interrupts instead of the product
  route. `refuses_echo_mode` now refuses only whole-system-output modes (`webrtc`, unknown)
  without a separate output device; `voxatest doctor` PASSes DTLN and WARNes `webrtc` without a
  device.
- **A leaked echo word could still interrupt her (Bug 3, `voxa/bargectl.py`).** As the second
  guard behind DTLN: words that overlap the current utterance heavily (>= 0.5 of the heard
  words) and sound like it letter for letter (>= 0.55) are her own echo, never an interrupt —
  the v05 pair "5 times 4 is 20." heard as "5 times more." no longer cuts her reply. A stop
  word or the bare wake word always beats the text (task A2: a person saying "stop" over her
  saying "stop" must always interrupt).

## Tests in this build

- Python suite: **4338 passed, 60 skipped** (`/Voxa/.venv/bin/python3 -m pytest -q -p
  no:cacheprovider tests`) — rc3's 4324 plus the regression tests below; each fails on the old
  code and passes on the new.
  - `tests/test_playbin_render_reference.py` (Bug 1): drives the real GStreamer in a subprocess
    (fakesink — no sound, no devices) over both shipped speech paths, `piece` (prepared file
    through playbin) and `whole-reply` (the streaming appsrc pipeline), each with the
    conversation muted True and False (the v05 lines were `path='whole-reply' muted=True`). The
    reference buffer holds her samples: attached, non-silent, complete, and sample-exact at the
    positions the sink received them. It fails on rc3 exactly where the live run failed:
    `the render tap did not attach on the piece path`.
  - `tests/test_voxatest_echo_on.py` (Bug 2): the guard allows DTLN/voxa/aec3/off, refuses
    webrtc/unknown without a device, and the preflight no longer stops a DTLN run; offline
    proof on the bench room audio (tests/anc_signals.py) with a real speech clip as the prompt:
    DTLN removes her echo (>= 15 dB in echo-only regions) while the prompt survives (<= 6 dB
    in its windows) — the prompt is not in the reference and a canceller that cannot see it
    does not remove it.
  - `tests/test_bargein_text_echo_veto.py` (Bug 3): the logged pair stays OWN_VOICE, a near-
    exact leak of her sentence tail stays OWN_VOICE, while "stop" over her "stop" and an
    unrelated interruption still INTERRUPT.
- GStreamer runtime check (the Flatpak case): the tap's elements — `tee`, `queue`, `capsfilter`
  (coreelements), `appsink` (app), `audioconvert`, `audioresample`, `autoaudiosink`
  (pulseaudio), `volume` — are present in the `org.gnome.Platform 50` runtime the bundle uses
  (verified under the installed runtime's `gstreamer-1.0` folder).
- `python3 tools/release_check.py`: **OK** — `release metadata OK: version 0.1.9, bundle
  Voxa-0.1.9-x86_64.flatpak`.

## Install this bundle

```
flatpak install --user --bundle /home/rhy/Voxa-0.1.9-rc4-local.flatpak
```

It shares the app id `io.github.crhy.voxa` with the Flathub app, so installing it takes the
place of your 0.1.8 (or an earlier local rc) for the desktop entry. It is a one-off local
install: it will not update itself from a remote.
