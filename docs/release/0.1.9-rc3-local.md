# Voxa 0.1.9 rc3 — local Flatpak (not published)

This is a **local test bundle** for 0.1.9, built from this checkout and **not** pushed to
Flathub or the GitHub Pages repo. It is rc2 plus the four voice-loop fixes from issue #130
(branch `strata/v03-voxa-rc2-silent-speech-fix`). Use it to try the repaired hearing loop on
your own machine; it never auto-updates and never overwrites the Flathub 0.1.8 you had.

## What is in it

Everything in rc2 (`docs/release/0.1.9-rc2-local.md`): APP_VERSION `0.1.9`, the whole hearing
chain (f163..f183, #72), the DTLN-aec default echo stage (h04), the hands-free roadmap and the
Ollama installer gate — then the four fixes below. See `docs/release/0.1.9-loop-audit.md` for the
measured root causes and the test that gates each one.

New since rc2 (issue #130, the voice-loop audit):

- **Silent playback / self-interruption (Bug 1, `voxa/timeline.py`).** The render tap that feeds
  both the speaker and the echo reference failed to attach on GStreamer 1.28 — a `queue` with no
  `async` property threw, and `Pad.link` returning `PadLinkReturn.OK` (an int `0`) was misread as
  failure. The reference stayed silent ("reference silent: no echo possible"), so with no echo
  possible a bare level rise was read as the user and Voxa cut her own reply off. The tap now
  attaches (guarded `async` + a `_pad_link_ok` helper) and audio reaches both the sink and the
  reference.
- **Barge-in on an empty transcript (Bug 2, `voxa/bargectl.py`).** A level rise with `heard=''`
  right after `gate-open` interrupted her. The transcript is the only thing that decides what
  happens to her words, so an empty, wake-word-only or hesitation/noise-only transcript is now a
  HOLD, never an INTERRUPT. A bare `stop` or `open the library` still always interrupts.
- **Web search returned nothing (Bug 3, `voxa/websearch.py`).** The `html.duckduckgo.com/html/`
  endpoint now answers these POSTs with a `202` anti-bot anomaly page (0 results). The search
  queries `lite.duckduckgo.com/lite/` with a plain GET and parses its `result-link` /
  `result-snippet` markup, falling back to `html/` only when lite yields nothing.
- **Stale echo_mode after upgrade (Bug 4, `voxa/config.py`).** A 0.1.8 profile stored
  `echo_mode: "webrtc"` (then the default); 0.1.9 defaults to the neural `dtln` stage. A profile
  that never picked an echo mode by hand migrates `webrtc` → `dtln`; one that explicitly chose
  `webrtc` carries a new `echo_mode_user_picked` marker and is left alone.

## Install this bundle

```
flatpak install --user --bundle /home/rhy/Voxa-0.1.9-rc3-local.flatpak
```

It shares the app id `io.github.crhy.voxa` with the Flathub app, so installing it takes the place
of your 0.1.8 (or an earlier local rc) for the desktop entry. It is a one-off local install: it
will not update itself from a remote.

## Going back to Flathub 0.1.8

Uninstall the local bundle and reinstall the published one:

```
flatpak uninstall --user io.github.crhy.voxa
flatpak install --user flathub io.github.crhy.voxa
```

That restores the Bazaar/Flathub **0.1.8** and its normal update path. Your Voxa settings and
saved hearing profiles under `~/.var/app/io.github.crhy.voxa/` are left in place; if you want a
clean slate, remove that folder too.

## Still open

The silent-playback fix is on the default **prerendered** face (both the "piece" and "whole-reply"
streaming paths). A **live/high** face renders through `playbin` (`_play_file`), where the
cross-bin render tap still cannot attach; it is recorded in `docs/release/0.1.9-loop-audit.md` as
still open, not fixed here. It is not the default path and does not affect the reported
silent-speech / self-interruption / empty-search bugs.
