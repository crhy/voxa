(issue #72 task v11d) and **not** pushed to Flathub. It is rc7 plus the v11d render-anchor,
hallucination-guard and idle-face work. It never auto-updates and never overwrites an

## What is in it (v11d)

- **A cross-script invention is never treated as new speech (voxa/bargein.py, commit
  `cdabe18`).** Whisper's English "hallucination" fired on sakura's *Japanese* reply
  ("The second part is the same as the original." over a Japanese utterance). The guard now
  rejects a candidate whose script disagrees with the sentence she is speaking
  (`scripts_disagree`, `HALLUCINATION_SCRIPT_VAD = 0.8`) **before** the delay-proven veto.
- **The pilot chirp seeds the exact lock, and it correlates the microphone against the
  KNOWN chirp template, not the map (voxa/audio.py, voxa/align.py; commits `91976d9`,
  `464cec1`, `906548a`).** The v11k run measured pilot prominence 14 at a spurious
  −4.2 ms travel because `_finish_pilot` correlated the microphone against the map read
  back through an unaligned reference. `.voxa-bench/echo_delay_probe.py` gets ~53 dB at
  −45 ms by cross-correlating the microphone against the **known** `speech.pilot_wav_bytes`
  template; `_finish_pilot` now does the same (travel = chirp onset in mic − chirp onset in
  map), and a ≥ 31.6 dB peak seeds the aligner confident at once (rhY's 21:48 note).
- **Turn events ride an unbounded control queue (commit `cf3023b`)** so 1695 drop-oldest
  hearing-drops no longer corrupt turn state; `echo-health` reports the mean over the reply.
- **Idle face debounce (commits `faff564`/`f728fd4`)** shows a face state only after it held
  ≥ 300 ms and traces `face-state frm=.. to=..` so the idle gate can count real changes.

### VoxaTest `--talk-over` — the answer metric was NOT met on this bundle

`.voxa-bench/venv-live/bin/python -m voxatest run --cases .voxa-bench/talkover5.json
--talk-over` ran all cases, but each ended `not_heard` / `No spoken reply was captured`:
barge.log shows `stt-done` then `no-wake heard='The directions to the library are
granted.'` — the microphone the app is configured to use (a "Galyimage Live camera") renders
VoxaTest's spoken `voxa …` prompt into a garbled declarative sentence that loses the wake
word, so the command router abstains and she never answers. This is a capture-path limit of
this desktop, not the barge-in logic: every captured reply still recorded
`self_interrupt_count: 0, kept_turn: true`, and the 22-character check above is the direct
proof that she does not interrupt herself. **`obeyed 5 of 5` is therefore NOT recorded
(0 of 4 answered).** A better microphone (the Blue Microphones the v11b measurements used)
or rhY's live session is needed to record it.

## Probe before / after

- **Before:** on the live lock the echo delay jumped reply-to-reply (lock_ms 40, None, 368,
  −40.7, −41.5, −93.5, −36.6 ms) as speech self-similarity re-searched ±400 ms of
  reflections; the app's pilot peak (`_energy_peak`, mic-vs-map) measured prominence 14 at a
  wrong −4.2 ms travel.
- **After:** `.voxa-bench/echo_delay_probe.py` correlates the microphone against the known
  chirp template and measures the chirp at one consistent **−45 ms** (spread **0.3 ms** over
  ≥ 5 chirps, ~53 dB); `_finish_pilot` now uses that same template method, so a clean pilot
  seeds the lock confident at once. (The probe needs the listening session active: run with
  no instance it reports `measured only 0 of 5 chirps`.)
